# Parallel Sprint Zero — Canon realignment

Status: complete for planning; implementation has not begun  
Prepared: 2026-08-03

## Human purpose

Parallel exists so people no longer have to carry the invisible weight of work alone. It protects attention, remembers what matters, helps people keep promises, and creates enough room for them to think, lead, create, and be present again.

Ara should not become the center of the user's life. She should quietly help the people, work, and potential that matter become central again.

## Founder direction recorded during Sprint Zero

The existing visual identity and strongest UX qualities are preserved. This includes:

- the cinematic Parallel mark and two-bar language;
- the calm, restrained palette and typography;
- generous negative space;
- Ara centered in a conversational canvas;
- task-specific views that appear only when they support the conversation;
- Today as the operating overview rather than turning Ara's page into a dashboard;
- restrained, stateful motion and a coherent voice presence.

The overhaul changes the platform beneath and around that visual language: identity, trust, permissions, memory, background work, evidence, action safety, onboarding behavior, and the way value is delivered.

## Governing interpretation

Canon Version 1.0 governs product behavior and architecture. Existing implementation references remain evidence about what has already been built, not authority to contradict Canon.

Visual continuity does not mean behavioral continuity. A surface may look familiar while its states, permissions, evidence, and lifecycle are rebuilt to meet Canon.

## Explicit conflicts

- Canon specifies no Start button on first arrival; an older UX reference and prior founder direction use one “Let's talk” button. The redesign will preserve the quiet visual arrival while treating immediate, conversation-led entry as the governing behavior. Returning access can retain one clear entry action.
- The current private demo resets the first relationship after a new release. Canon treats first launch as a genuine relationship milestone. Release resets remain demo-only and must never affect production memory.
- The prototype permits real calendar and email writes after conversational approval. Canon begins with read-only observation and earns broader authority over time. Existing writes remain available only inside an explicit demo authority profile until the staged trust engine replaces the current behavior.
